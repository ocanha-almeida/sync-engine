# 📄 Reports, Sync Logs, and Large File Audit Guide

Sync Engine is designed for total transparency. Every critical system action generates an audit record—whether as a continuous journal produced by the silent background daemon or as an on-demand text report generated at your request. The system isolates log files by account profile and standardizes them with precise timestamps, enabling you to inspect everything that occurs behind the scenes.

---

## 1. Where Are Reports and Logs Stored? (Report Save Location)

By default, all reports and logs generated by Sync Engine are stored in a dedicated folder within the application directory. However, you can redirect the storage destination to any path on your machine.

**How to change the global storage location:**
1. Open the interactive wizard: `sync-engine config`.
2. Navigate to **Global Settings**.
3. Select **Change Report Save Location**.
4. Enter the absolute path of the directory where you want your logs consolidated (e.g., `C:\My_Sync_Logs` on Windows, or `~/Documents/Reports` on Linux).

From that point onward, all newly generated reports and continuous sync logs will be written to this specified directory.

---

## 2. Continuous Synchronization Log (Sync.log)

While one-off text reports (`.txt`) are generated for explicit user actions (such as simulation runs or filename sanitization), `.log` files (e.g., `[account_name]_sync.log`) serve as the official operational journals of the background daemon.

**How the Sync Log functions:**
* **Silent Logging:** Every time the Background Motor wakes up to inspect your folders, it records its findings in this journal—noting whether new files were detected, transfer operations were initiated, or the remote was already fully up to date.
* **Per-Account Isolation:** Each configured account profile maintains its own dedicated `sync.log` file, preventing log entries from interleaving across different cloud remotes.
* **Auto-Rotation (Smart Pruning):** You do not need to worry about log files exhausting your storage space over time. The engine automatically rotates log files when they reach a specific file-size ceiling, archiving or trimming old entries so you always have access to recent operational history without wasting disk space.

---

## 3. Large File Auditing (Large File Reports)

If you configured an upper file size limit (`MAX_SIZE`) for an account profile (for example, bypassing files larger than 500 MB), Sync Engine automatically skips them during sync passes. To identify **which files were excluded**, use the Large File Audit tool:

1. From the main menu, navigate to the **Maintenance** section.
2. Select **Large File Reports**.
3. Choose the account profile you want to audit.
4. The system generates an audit document (`_ultimo_relatorio_tamanho.txt` or `_last_size_report.txt`) detailing the filename, exact directory path, and size in megabytes (MB) or gigabytes (GB).

---

## 4. The Sync Engine Logging Ecosystem

Inside your configured reports directory, you will find several categories of logs and reports, consistently prefixed with the profile name:

* **`[account]_sync.log`**: The continuous operational journal of the background daemon.
* **`[account]_ultima_sincronizacao_manual.txt`**: The execution output from the most recent on-demand manual sync (`sync-engine now`).
* **`[account]_ultimo_dry_run.txt`**: The detailed simulation report generated by Safe Simulation Mode (`sync-engine test`), showing pending changes without altering data.
* **`[account]_ultimo_relatorio_higienizador.txt`**: The audit trail generated by the Filename Cleaner (`sync-engine clean`), listing sanitized names and resolved collisions.
* **`migracao_*.txt`**: Detailed transfer manifests generated during direct Cloud-to-Cloud Migration operations.

## 5. Practical Use Cases

### Example 1: Verifying Silent Background Activity
You configured your "Work" account to sync every 10 minutes in the background, but spent the morning reading documents without creating or modifying local files.
**The Solution:** To confirm that the background motor is active and monitoring the folder, open `Work_sync.log`. You will see timestamped entries documenting every wake-and-check cycle, confirming that the engine inspected the directory, found no modifications, and returned to idle mode.

### Example 2: Remote Log Monitoring
You deployed Sync Engine on a headless office server (Linux), but want to monitor synchronization logs and health reports from your mobile device or laptop.
**The Solution:**
1. Open Sync Engine on the server: `sync-engine config`.
2. Go to **Global Settings**.
3. Set the **Report Save Location** to a folder inside an already-synchronized cloud directory (e.g., `~/gdrive/Server_Logs`).
4. Whenever the system runs or generates a new `sync.log`, the updated logs will sync to your cloud account, giving you remote access anywhere.

### Example 3: Auditing Excluded Large Files
Your account enforces a 2 GB file ceiling, and a video render did not sync to the cloud.
**The Solution:** Run the **Large File Reports** tool. The resulting report pinpoints the exact file path and file size, confirming whether it exceeded the configured threshold.
